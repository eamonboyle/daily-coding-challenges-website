# AGENTS.md

## Cursor Cloud specific instructions

This repo is a single product, **Daily Coding Challenges** (Next.js web app + a code-execution microservice + Postgres). See `README.md` for the full architecture and command reference. Notes below cover only non-obvious, durable caveats for running it in this cloud environment.

### Services and how to run them (local mock mode)

The documented dev path is **mock mode** (no Docker, OpenAI, or Clerk needed). Env lives in `.env.local` (gitignored), created by copying `.env.example`. Three processes are needed for the end-to-end flow:

| Service | Dir | Dev command | Port |
| --- | --- | --- | --- |
| PostgreSQL | — | `sudo pg_ctlcluster 16 main start` | 5432 |
| Code execution server | `code-execution-server/` | `EXECUTION_MODE=mock PORT=5000 npm run dev` | 5000 |
| Next.js app | repo root | `npm run dev` | 3000 |

End-to-end entry point: http://localhost:3000/challenges (mock mode auto-seeds a user and serves the fixture "Sum Array Elements" challenge). The `MOCK` badge in the header confirms mock mode.

### Non-obvious caveats

- **Postgres is not auto-started on boot.** It is installed natively (apt, PostgreSQL 16), but there is no init/systemd runlevel here, so start it manually each session: `sudo pg_ctlcluster 16 main start`. The dev role/database (`daily_coding_challenge` / `daily_coding_challenge`, password `daily_coding_challenge`) already exist and match `DATABASE_URL` in `.env.example`.
- **Prisma CLI does not read `.env.local`.** `prisma.config.ts` uses `import "dotenv/config"`, which only loads `.env`. Any Prisma CLI command (`prisma db push`, `prisma generate`, `prisma migrate`) needs `DATABASE_URL` supplied inline, e.g. `DATABASE_URL="postgresql://daily_coding_challenge:daily_coding_challenge@localhost:5432/daily_coding_challenge" npx prisma db push`. The Next.js app itself reads `.env.local` normally.
- **After schema changes**, run `... npx prisma db push` (inline `DATABASE_URL` as above) and `npx prisma generate`. The generated client lives in `node_modules`, so it is regenerated by the startup update script after a fresh `npm install`.
- **`npm run lint` is currently broken** and is a pre-existing repo/config issue (not an environment problem): `eslint .` with ESLint 9 + `.eslintrc.json` + `eslint-config-next@16` fails under both flat-config and legacy modes. Type checking still runs as part of `npm run build` (`next build` runs `tsc`). Use `npm run build` to catch type errors.
- **Smoke test without any servers:** `npm run verify:mock` exercises the mock executor + test-case normalization in-process.
- **Docker execution mode** (`EXECUTION_MODE=docker`) and the full `docker compose up` stack require a Docker daemon, which is not installed here. Use mock mode for local development.
